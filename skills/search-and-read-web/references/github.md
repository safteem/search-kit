# Поиск открытых программ (GitHub)

Когда: подобрать open source программу или библиотеку под задачу, найти замену платному сервису, сравнить проекты,
проверить, живой ли проект. Скрипт `scripts/gh_repos.py` — бесплатный API GitHub без ключа (если в окружении есть
`GITHUB_TOKEN`, берёт его: лимит 5000 запросов в час вместо 60).

## Правила (и зачем)
1. **Задача и способ использования — до поиска.** Какие функции обязательны, где будет работать, как пользователь
   собирается программу использовать (для себя, в работе, встроить в свой продукт). Не ясно — один вопрос:
   от этого зависит, подходит ли программа и её лицензия.
2. **Кандидаты из четырёх мест, всегда все:** каталоги замен (openalternative.co, awesome-selfhosted и другие
   awesome-списки, alternativeto.net), обзоры через Google и Keenable, поиск самого GitHub, поиск Reddit (ветки
   «альтернатива X», «что посоветуете для Y», посты авторов «я сделал …» — там свежие проекты раньше обзоров). В GitHub искать по
   категории, а не списком функций: все слова ищутся разом, «crm whatsapp sms» даёт пусто, а `find "crm"`,
   `find "topic:omnichannel"`, `find "marketing automation"` по звёздам находят и зрелые проекты без обзоров.
   Проект младше полугода или с горсткой звёзд — отдельной строкой «смотреть позже», не в рекомендацию.
3. **Живые цифры — только из API GitHub,** не из обзоров и кэша: там звёзды устаревшие. `gh_repos.py check a/b c/d …`
   — таблица по списку (звёзды, последнее изменение кода, лицензия, архив, открытые задачи), ~1 поисковый запрос
   на 10 проектов. `--deep` — ещё три цифры живости (последний релиз, коммиты за 90 дней, число участников),
   3 обычных запроса на проект, для финалистов. Это не разбор кода: код и устройство изучаем отдельно и только
   у выбранных к установке.
4. **Живость по нескольким признакам:** код менялся в последний месяц, есть релизы, коммиты за 90 дней, участников
   больше горстки (проект одного автора умирает вместе с его интересом), не архив. Звёзды — интерес, а не качество:
   их накручивают, и они копятся годами у заброшенных проектов.
5. **Лицензия — по тексту, а не по значку,** и сверить с тем, как пользователь собирается программу использовать.
   «Свой текст» (NOASSERTION) — читать LICENSE. Частые ловушки: платные папки `enterprise/`, `ee/`, BSL, SSPL,
   fair-code, дописанные запреты; на вопрос «а можно ли так» — FAQ лицензии самого проекта, не пересказ и не память.
6. **«Умеет из коробки» — по документации, а не по заголовку README:** функция бывает платным плагином, бетой или
   «скоро». Задачи и запросы на изменения по слову функции (`gh_repos.py issues <repo> <слово>`) показывают, есть ли
   она, просят ли её, не убрали ли.
7. **Опыт людей обязателен:** Reddit (r/selfhosted и тематические), YouTube (установка, «полгода спустя»,
   «почему ушёл»), Hacker News — по `references/youtube-reddit.md`. Партнёры и аффилиаты часто рассказывают
   полезное: брать, помня их интерес, громкие утверждения сверять с документацией.
8. **Цена владения в ответе:** сервер, обновления, бэкапы, платные части, время на допиливание — рядом с ценой
   платного сервиса, который заменяем (из контекста или одним поиском).
9. **Ответ:** сначала что это за программы одной фразой и что умеет каждая, потом таблица (звёзды, последнее
   изменение, лицензия, что есть из коробки, чего нет) с датой цифр, рекомендация с главным минусом,
   «смотреть позже», что не проверено.
10. **Ничего не устанавливать и не клонировать** без «да» пользователя.
